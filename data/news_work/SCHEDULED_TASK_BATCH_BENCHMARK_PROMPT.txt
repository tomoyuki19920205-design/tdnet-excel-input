Company News Monitor batch benchmark専用promptです。このpromptは、対応setup fileが実行したroute commandから`mode=benchmark`が返った場合だけ使用してください。Production routeでは使用禁止です。

最初に次の共通research/schema contractを全文読み、会社IR・主要ニュースのsource priority、company_news_v1 field、enum、fixed-window validationを守ってください。

C:\Users\takuy\OneDrive\tdnet-excel-input\data\news_work\SCHEDULED_TASK_COMMON_PROMPT.txt

ただし保存transportは本promptを優先します。`data/news_inbox`、Production assignment、Production queue、decision_db.db、Supabaseへ保存・変更してはいけません。snapshotが返す`temp_path`と`output_path`だけを使用してください。両pathは`data/news_benchmark_inbox`配下でなければ処理を停止してください。

route結果のtask_idを使い、run開始時に次を1回だけ実行します。

`.\.venv\Scripts\python.exe tools/company_news_batch_benchmark.py snapshot --task-id <task_id>`

statusがbusyなら調査・保存せず終了します。snapshot_createdなら、返されたassignments arrayをimmutable snapshotとして保持します。assignment fileやbenchmark task queueをrun途中に再読込せず、snapshot_company_countを超えるN+1社目を処理しません。

各assignmentを記載順に独立処理します。Web research直前に次を実行します。

`.\.venv\Scripts\python.exe tools/company_news_batch_benchmark.py research-start --task-id <task_id> --run-token <run_token> --assignment-id <assignment_id>`

assignmentのticker/company_nameだけを、固定されたsearch_fromからsearch_toまで調査します。期間をcurrent dateまで延長しません。調査完了直後、JSON validation/saveより前に次を実行します。

`.\.venv\Scripts\python.exe tools/company_news_batch_benchmark.py research-finish --task-id <task_id> --run-token <run_token> --assignment-id <assignment_id>`

snapshotに`strategy_version = company_news_research_strategy_v2`がある場合だけ、以下のCoverage Contractを追加適用します。strategy_versionがない従来runはこの追加contractやstrategy telemetry fileを使用しません。

各社へ独立したreserved budgetを割り当て、他社の調査量によって省略しません。Official-firstは2～3 search actions、Targeted second passは1～3 actions、合計は1社3～6 actionsです。wall-clock sleepで時間を水増ししてはいけません。

Stage A（Official-first）では、会社名・tickerから会社IR、会社news/press release、TDNET/適時開示、必要な法定開示を確認し、会社名と`site:go.jp`を組み合わせた一般的なgovernment queryを必ず1回含めます。特定agency名による固定branchは作りません。公式domainを特定したら同じcompany pass内で再利用します。

Stage B（Targeted second pass）では、assignmentのsectorだけを広く検索せず、Stage Aで確認した公式事業説明と公開company metadataから、収益へのtransmission channelを説明できるdriverを最大3 groups抽出します。使用可能なgroupは、`demand_customer_order`、`pricing_cost_supply`、`industry_regulation_competition`です。core product、customer industry、input/raw material、capacity、pricing、regulation、commodity、industry cycleから該当するdriverだけを選びます。material candidateが0、external driver sourceが0、明確なdriver exposureが未確認、またはsource diversity不足のいずれかではsecond passを省略しません。

Official coverageとexternal coverageの両方がcompleteになるまで、そのcompanyの調査完了および`items=[]`確定は禁止です。eventを1件発見しても終了せず、固定window全体を最後まで確認します。canonical schema自体にitems件数のhard capはありません。Strategy v2では1社あたりcandidate最大20件・final material event最大10件とし、複数eventを保持しながら無制限出力を防ぎます。上限超過はfailureとして記録し、eventを黙って切り捨てません。

各candidateがどのstageで発見されたかを記録します。正常payloadをtemp_pathへ作成するのに加え、次のbenchmark-only telemetryをassignmentの`strategy_telemetry_temp_path`へ保存します。`strategy_telemetry_path`へ直接保存してはいけません。finalize commandが両fileを検証してatomicに確定します。

```json
{
  "schema_version": "company_news_benchmark_strategy_telemetry_v2",
  "strategy_version": "company_news_research_strategy_v2",
  "assignment_id": "<assignment_id>",
  "ticker": "<assignment ticker>",
  "official_queries_attempted": ["<actual query; 2 to 3 entries including site:go.jp>"],
  "official_sources_found": ["<verified http/https URL>"],
  "official_coverage_complete": true,
  "government_search_attempted": true,
  "external_queries_attempted": ["<actual driver query; 1 to 3 entries>"],
  "external_sources_found": ["<verified http/https URL>"],
  "external_coverage_complete": true,
  "driver_groups": [
    {
      "driver": "<dynamically derived driver>",
      "query_group": "<one allowed group>",
      "transmission_channel": "<why the driver can affect revenue, volume, price, margin, cost, capacity, customer demand, or regulation>"
    }
  ],
  "source_diversity": ["<source type actually checked>"],
  "candidate_event_count": 0,
  "final_event_count": 0,
  "no_news_gate_pass": true,
  "window_review_complete": true,
  "stopped_after_first_event": false,
  "official_stage_elapsed_seconds": 0.0,
  "targeted_stage_elapsed_seconds": 0.0,
  "total_research_elapsed_seconds": 0.0,
  "candidate_provenance": []
}
```

`candidate_provenance`は全candidateをindex 0からexactly once含め、各要素を`candidate_index`、`stage`（`official_first` / `targeted_second_pass` / `existing_general`）、`selected_for_output`、`headline`、`source_url`で記録します。selected数はcanonical payloadのitems数と一致させます。新規candidateは既知集合にないという理由だけで除外せず、通常のmateriality contractで判定します。後段評価が未裁定candidateを自動的に誤検出扱いすることはありません。

正常結果は共通contractのcanonical company_news_v1だけをsnapshotのtemp_pathへ保存します。run_idとtask_idはassignment_id、tickerはassignment ticker、sources_checked_countは実際に確認できたsource数です。重要な新情報がない場合だけitems=[]にします。

operational failureをitems=[]で偽装してはいけません。failureの場合は次の専用sidecarをtemp_pathへ保存します。

```json
{
  "schema_version": "company_news_benchmark_failure_v1",
  "task_id": "<taskNN>",
  "slot_id": "<snapshot slot_id>",
  "assignment_id": "<snapshot assignment_id>",
  "ticker": "<snapshot ticker>",
  "company_name": "<snapshot company_name>",
  "error_type": "<non-empty classification>",
  "error_message": "<specific non-empty message>",
  "sources_attempted": ["<URL or source name>"],
  "created_at": "<timezone付きISO-8601>"
}
```

temp file作成後、正常結果は次のcommandでschema validationとatomic final saveを行います。

`.\.venv\Scripts\python.exe tools/company_news_batch_benchmark.py finalize-company --task-id <task_id> --run-token <run_token> --assignment-id <assignment_id>`

failure sidecarは`--failure`を追加します。finalizeが成功する前にfinal filenameへrenameしません。1社が失敗しても残りのsnapshot assignmentを続行します。

全snapshot assignmentをfinalizeした後、次を1回だけ実行してtask-level telemetryを確定しguardをreleaseします。

`.\.venv\Scripts\python.exe tools/company_news_batch_benchmark.py release-task --task-id <task_id> --run-token <run_token>`

benchmark CLIが記録する外部観測可能な時刻だけを使います。モデル内部のhidden reasoningやtoken thinking timeを推測・記録しません。
